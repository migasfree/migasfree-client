# Contributing to Documentation

We follow the [Diátaxis framework](https://diataxis.fr/) for our documentation. This ensures that all content serves a specific user need.

When contributing documentation, please categorize your content into one of the following four quadrants:

## 1. Tutorials (Learning-oriented)

**Goal:** Take the user by the hand and lead them to a successful outcome.

- **Location:** `docs/tutorials/`
- **Style:** "First, do this. Then, do that."
- **Example:** [Your First Synchronization](../docs/tutorials/first-sync.md)

## 2. How-To Guides (Problem-oriented)

**Goal:** Show the user how to solve a specific problem or complete a task.

- **Location:** `docs/how-to/`
- **Style:** A recipe or checklist. Assumes the user knows what they want to achieve.
- **Example:** [Troubleshooting Common Issues](../docs/how-to/troubleshooting.md)

## 3. Reference (Information-oriented)

**Goal:** Describe the machinery strictly and accurately.

- **Location:** `docs/reference/`
- **Style:** Dry, factual, unstructured. Like a dictionary or map.
- **Example:** [Configuration Options](../docs/reference/configuration.md)

## 4. Explanation (Understanding-oriented)

**Goal:** Clarify concepts, background, and context.

- **Location:** `docs/explanation/`
- **Style:** Discursive, connecting ideas. "Why things are the way they are."
- **Example:** [Architecture Overview](../docs/explanation/architecture.md)

---

## Formatting

- Use **Markdown**.
- Use **Relative Links** to other docs (`[Link](../folder/file.md)`).
- Use **Code Blocks** for commands and configuration snippets.
- Keep lines wrapped or infinite? Use soft wraps (don't break lines manually unless strictly needed).
